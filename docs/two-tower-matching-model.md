# SKU–达人匹配模型 · 设计方案（双塔 + 外积 + CNN）

> 状态：**设计阶段**。架构与特征方案已确定，模型代码尚未实现。

## 1. 问题定义

达人运营依赖人工经验给 SKU 挑达人，难以复用，也难以扩展到上千人的达人库。模型要预测每个 **(SKU, 达人)** 组合的价值（相对销量 / ROI），**辅助**运营决策，而不是替代运营判断。

这是供需双边的**匹配预测**问题，不是机制设计：这里没有激励相容的问题，只有对组合价值的预测。

## 2. 数据

面板数据：日期、达人 ID、达人特征（粉丝量、内容特征、带货品类）、销售、投放消耗、商品特征（品类、转化率、价格）、ROI。每天约 2 万条，连续 1 个月，约 60 万行。其中大部分是同一批组合的重复记录。

**v1 决定：** 先把面板数据聚合成每个 (SKU, 达人) 一行，做成静态匹配预测；时序建模作为后续扩展。

### 稀疏度诊断（在聚合后的数据上做）
- 实际出现的 (SKU, 达人) 组合数，占理论组合空间（约 2000 个 SKU × 达人总数）的比例
- 每个组合被记录的频次分布（决定是否把"观测天数"作为特征）
- target 的分布形态（长尾则做 log 变换）

### 需要人工补充的标签（按优先级）
1. 大促 / 节日标记
2. 内容形式（直播 / 短视频 / 图文）
3. 达人调性与垂类（测评向 / 种草向 / 搞笑向 / 知识向）
4. 合作阶段（首次合作 / 长期合作）
5. 数据质量异常标记（零投放但高销量、疑似刷量）
6. SKU 生命周期阶段（新品 / 爬坡 / 成熟 / 清仓）

打标之前先做两件现有列就能做的事：用去重后的真实组合数重跑稀疏度诊断；计算投放消耗与销量的相关系数，量化混淆有多严重。

## 3. 特征工程

| 类型 | 处理方式 |
|---|---|
| 低基数类别（品类、价格带、生命周期） | one-hot 或 embedding，维度取 `min(50, (类别数+1)//2)` |
| 高基数（SKU ID、达人所属机构） | SKU embedding 作为可选信号，用"未见过的 SKU"做有/无对比实验后决定是否保留；机构等字段用 target encoding，并用 K-fold 防标签泄漏 |
| 达人 ID | **不做 embedding**，让模型学特征组合而不是记住"是谁"，才能泛化到新达人 |
| 多标签（达人历史带货品类） | 转成概率向量，与当前 SKU 品类做点积 / 余弦，压缩成一个"品类匹配度"特征 |
| 数值特征 | 标准化；粉丝量等重尾分布先 log 再标准化 |
| 缺失值 | 用同类达人（如同粉丝量区间）的均值填充，并加"是否缺失"标志位，不填 0 |
| 混淆变量（投放消耗、是否大促） | 不进交互部分，在 CNN 之后拼接 |

## 4. 模型架构

1. **商品塔（MLP）：** 品类、价格带 embedding + 标准化数值特征 → 2 层 MLP → 32 维 `e_sku`
2. **达人塔（MLP）：** 粉丝量、互动率、品类匹配度等 → 32 维 `e_kol`（不含达人 ID）
3. **外积层：** `e_sku ⊗ e_kol` → 32×32 交互矩阵。第 [i, j] 个元素表示 SKU 第 i 维与达人第 j 维的交互强度，这张图有局部结构，CNN 才有意义（思路来自 ConvNCF）。如果把无顺序的表格特征直接拼接再过 CNN，卷积的局部假设不成立
4. **CNN 层：** 2–3 层 3×3 卷积 + ReLU + 池化，再 flatten
5. **拼接控制变量：** 投放消耗、是否大促在此处并入
6. **输出层：** 全连接，输出一个回归值

## 5. 训练与验证

- **target：** 销量 / 该达人历史均值（相对指标）再做 log1p。ROI 已经按投放消耗归一化，作为对照 target：两者结论一致则互相印证，不一致则先想清楚业务更看重哪个
- **数据划分：** 按达人分组划分（验证集含训练时没见过的达人），与随机划分对比；差距大说明模型在记达人
- **baseline：** 同一划分下训练 FM / GBDT，比较 MAE / RMSE。如果深度模型没有明显提升，这个结论也会写进结果
- **公平性：** 按达人粉丝量分桶（头部 / 腰部 / 尾部）看预测误差，检查是否对尾部达人更差

## 6. 设计原则

- 输出可验证的中间结果（预测销量），不强制输出"最优配对"
- 泛化到没见过的达人（冷启动），而不是记忆达人 ID
- 显式评估对头部达人 / 高曝光 SKU 的偏向（popularity bias）

## 7. 已知风险

- 大促、投放消耗带来的混淆（第 3、5 节已有处理）
- 组合空间稀疏（稀疏度诊断 + 内容特征泛化）
- 如果后续融合多个指标作为 label，权重需要依据；v1 使用单一 target
- 数据量未必支撑深度学习，baseline 对比是必做步骤
